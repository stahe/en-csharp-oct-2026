    3. The Basics of the C# Language

    3.1. Introduction

    We’ll start by treating C# as a traditional programming language. We’ll cover classes in the next chapter. In a program, there are two main components:

    • data;
    • the instructions that manipulate them.

    We generally strive to separate data from instructions:

    All the examples in this chapter are single-file applications: a single file, [.cs], without a project file ([.csproj]), which is run using the command [dotnet run bases-01.cs]. This feature, introduced with .NET 10, was covered in the previous chapter. The examples are located in the [03-bases] folder of the course code. They run in the French locale (fr-FR), as on a French Windows machine: real numbers are displayed with a decimal point.

    Above, we have listed the equivalent .NET types for each C# type, marked with (S) if the type is a structure and (C) if it is a class. We see that there are two possible names for a 32-bit integer: [int] and [Int32]. The type [int] is a C# keyword. [Int32] is a structure belonging to the [System] namespace: its full name is [System.Int32]. The type [int] is a C# alias that refers to the structure .NET [System.Int32]. Similarly, the C# type [string] is an alias for the .NET [System.String] type. [System.String] is a class, not a structure. The two concepts are similar, but with the following fundamental difference:

    • a variable of type structure directly contains its value: this is called a value type;
    • a variable of a class type contains the address of the object (its reference); this is known as a reference type.

    In addition, there are two less common types:

    • [nint] and [nuint] (C# 9) are signed and unsigned integers whose size is that of a memory address: 4 bytes on a 32-bit system, 8 bytes on a 64-bit system. They are primarily used to interact with native code;
    • [System.Half] (.NET 5) is a 2-byte, low-precision floating-point number used in graphics computing and machine learning. It is not a predefined language type: it does not have a C# keyword.

    A structure, like a class, is a complex type with properties and methods. Thus, we can write:

    1
    string? nomDuType = 3.GetType().FullName;

    The literal 3 is by default of type C# [int], and therefore of type .NET [System.Int32]. This structure has a method [GetType()] that returns an object describing the data type. Among the properties of this object, [FullName] is the full name of the type. The literal 3 is therefore a more complex object than it appears at first glance. The question mark in [string?] will be explained a little later.

    In the source code, floating-point numbers are always written with a decimal point, regardless of the system’s locale.     A standard string literal can contain escape sequences introduced by the \ character: "\n" represents the end-of-line character and not the sequence of the two characters \ and n, "\t" represents a tab, "\"" represents a double quote, and "\\" represents the \ character itself.     C# now offers two other types of strings:

    • the interpolated string (C# 6) $"...": expressions enclosed in curly braces are evaluated, and their values are inserted into the string. An expression can be followed by a format specifier after the colon: [$"{d1:F2}"] displays the floating-point number [d1] with two decimal places. This is the most readable way to construct a string, and we will use it from now on instead of the {0}, {1}, ... formats;
    • The raw string (C# 11) """...""" : It begins and ends with at least three quotation marks. It can contain quotation marks and unescaped \ characters, and can span multiple lines. Spaces preceding the closing quotation marks are removed from each line, allowing the text to be indented with the code. This is very useful for writing JSON, SQL, or HTML.

    3.3.3. Data Declaration

    3.3.3.1. Role of declarations

    A program manipulates data characterized by a name and a type. This data is stored in memory. When the program is compiled, the compiler assigns each piece of data a memory location characterized by an address and a size. It does this based on the declarations made by the programmer. Furthermore, these declarations allow the compiler to detect programming errors. Thus, the operation [x = x * 2;] will be declared invalid if [x] is a character string.

    3.3.3.2. Declaring Constants

    The syntax for declaring a constant is as follows:

    1
    const type nom = valeur;

    For example:

    1
    const double TauxTva = 0.2;

    Why declare constants?

    • The program is easier to read if the constant is given a meaningful name;
    • it is easier to modify the program if the “constant” needs to be changed. Thus, if the rate of TVA changes to 0.25, the only modification needed will be to the statement that defines its value: [const double TauxTva = 0.25;]. If 0.2 had been used explicitly in the program, numerous statements would need to be modified.

    The value of a constant must be known at compile time: a number, a string, a Boolean, or an expression that can be calculated from other constants. By convention, in .NET, constant names begin with a capital letter.

    A variable is identified by a name and is associated with a data type. C# distinguishes between uppercase and lowercase letters: the variables [FIN] and [fin] are different.

    Variables can be initialized when they are declared. The syntax for declaring one or more variables is:

    1
    type variable1 = valeur1, variable2 = valeur2, ...;

    1

    3.3.4. Nullable Types

    A variable of a value type, such as [int], always contains a value. It is sometimes useful to be able to express the absence of a value: an unknown age, an empty field in a database. The type [int?] (C# 2) is the type [int] with the value [null] added to it, which means “no value.” This is referred to as a nullable value type. The principle applies to all value types: [double?], [bool?], [DateTime?], ...

    A variable of a reference type, such as [string], can always have the value [null]: this means that it does not reference any object. Attempting to use a member of such a variable—for example, its property [Length]—will result in a runtime error ([NullReferenceException]), one of the most common errors in C#. Starting with C# 8, the compiler can help prevent this: with nullable reference types—enabled by default in projects created using the [dotnet new] command and in single-file applications—

    • the type [string] denotes a string that never evaluates to [null];
    • the type [string?] refers to a string that can be [null].

    The compiler tracks the possible values of variables and issues a warning when there is a risk of using the value [null]: assigning [null] to a variable [string], using [Length] on a variable [string?] that has not been tested, etc. Unlike [int?], [string?] does not create a new type at runtime: it is a directive intended for the compiler.

    3.3.6. Data Arrays

    A C# array is an object that allows data of the same type to be grouped under a single identifier. It is declared as follows:

    1
    Type[] tableau = new Type[n];

    [n] is the number of data elements the array can contain. The syntax [tableau[i]] refers to data element number i, where i belongs to the range [0, n-1]. Any reference to data item [tableau[i]] where i is not in the range [0, n-1] causes an exception. Upon creation, each element of the array is assigned the default value for its type: 0 for numbers, [false] for booleans, and [null] for reference types. An array can be initialized at the same time it is declared:

    1
    int[] entiers = new int[] { 0, 10, 20, 30 };

    or, more simply:

    1
    int[] entiers = { 0, 10, 20, 30 };

    or, starting with C# 12, using a collection expression:

    1
    int[] entiers = [0, 10, 20, 30];

    We will use this last form from now on. Arrays have a property [Length], which represents the number of elements they contain.

    A two-dimensional array is declared as follows:

    1
    Type[,] tableau = new Type[n, m];

    where [n] is the number of rows and [m] is the number of columns. The syntax [tableau[i, j]] refers to element j in row i. The two-dimensional array can also be initialized at the same time it is declared:

    1
    double[,] reels = { { 0.5, 1.7 }, { 8.4, -6 } };

    The number of elements in each dimension is obtained using the method [GetLength(i)], where i=0 represents the dimension corresponding to the first index, i=1 represents the dimension corresponding to the second index, and so on. The number of dimensions is obtained using the property [Rank], and the total number of elements using the property [Length].

    An array of arrays (also known as a staircase array) is declared as follows:

    1
    Type[][] tableau = new Type[n][];

    The declaration above creates an array of n elements. Each element, [tableau[i]], is a one-dimensional array reference. These references are not initialized by the declaration above; they have the value [null]. Unlike a two-dimensional array, each row can have a different length.

    C# 8 introduced two convenient notations:

    • backward indexing: [tableau[^1]] is the last element, [tableau[^2]] is the second-to-last, and so on. [tableau[^1]] is equivalent to [tableau[tableau.Length - 1]];
    • the range: [tableau[1..3]] is a new array consisting of the elements with indices 1 and 2. The start index is included, and the end index is excluded. The bounds can be omitted: [tableau[2..]] ranges from index 2 to the end, and [tableau[..^1]] ranges from the beginning to the second-to-last element, inclusive.

    3.4.1. Writing to the Screen

    There are various instructions for writing to the screen:

    1
2
3
    Console.Out.WriteLine(expression);
Console.WriteLine(expression);

    where [expression] is any data that can be converted to a character string for display on the screen. All C# or .NET objects have a [ToString()] method that is used to perform this conversion. The [Write] method does the same thing as [WriteLine] without wrapping to the next line.

    Class [System.Console] provides access to screen-writing operations ([Write], [WriteLine]). It has two properties, [Out] and [Error], which are write streams of type [TextWriter]:

    3.4.5. Assigning the value of an expression to a variable

    Here we are interested in the operation [variable = expression;]. The expression can be arithmetic, relational, Boolean, string, etc.

    3.4.5.1. Interpretation of the assignment operation

    The operation [variable = expression;] is itself an expression that is evaluated as follows:

    • the right-hand side of the assignment is evaluated: the result is a value V;
    • the value V is assigned to the variable;
    • the value V is also the value of the assignment, now viewed as an expression.

    Thus, the operation [V1 = V2 = expression] is valid. Since the = operator is evaluated from right to left, we get [V1 = (V2 = expression)]. The expression [V2 = expression] is evaluated and has the value V. Its evaluation caused V to be assigned to V2. The next = operator is then evaluated as [V1 = V]. The value of this expression is still V; its evaluation causes V to be assigned to V1. Thus, the operation [V1 = V2 = expression] is an expression whose evaluation:

    • causes the value of [expression] to be assigned to the variables V1 and V2;
    • returns the value of [expression].

    This can be generalized to an expression of the form [V1 = V2 = ... = Vn = expression].

    They are compared character by character. The first inequality encountered between two characters results in an inequality of the same direction for the strings. Consider comparing the strings "Cat" and "Dog":

    • [StringComparison.CurrentCulture] (the default for [CompareTo]): follows standard cultural conventions for sorting text intended for users.

    3.4.5.7. Combination of Operators

    [a = a + b] can be written as [a += b]; [a = a - b] can be written as [a -= b]. The same applies to the operators /, %, *, <<, >>, >>>, &, |, ^. Thus, [a = a / 2;] can be written as [a /= 2;].

    3.4.5.8. Increment and Decrement Operators

    The notation [variable++] means [variable = variable + 1] or [variable += 1]. The notation [variable--] means [variable = variable - 1] or [variable -= 1]. When used in an expression, these operators have two forms:

    • [i++] (postfix): the value of the expression is the value of i before the increment;
    • [++i] (prefixed): the value of the expression is the value of i after the increment.

    3.4.5.9. The ternary operator?

    The expression [expr_cond ? expr1 : expr2] is evaluated as follows:

    • The expression [expr_cond] is evaluated. This is a Boolean expression;
    • if it is true, the value of the expression is that of [expr1], and [expr2] is not evaluated;

    3.4.5.12. Type Casting

    In an expression, it is possible to temporarily change the representation of a value. This is called “type casting.” The syntax for changing the type of a value in an expression is as follows:

    1
    (type) valeur

    The value then takes on the specified type. This results in a change in the value’s representation. We distinguish between:

    • Implicit conversions, performed automatically by the compiler when they do not result in any loss of information: from a [int] to a [long], from a [int] to a [double], from a [char] to a [int], and so on. The conversion from a [long] to a [double] is also implicit, although it may lose precision beyond 2⁵³;
    • explicit conversions, which may result in a loss of information and must be explicitly requested by the programmer using the (type) notation: from a [double] to a [int] (the decimal part is lost), from a [long] to a [int] (the most significant bits are lost), etc.

    By default, an overflow in an integer calculation or an integer conversion is not reported: the result is simply false. The keyword [checked], on the other hand, causes an overflow to trigger a [OverflowException] exception. It applies to an expression, [checked(expression)], or to a block of instructions, [checked { ... }].

    3.5.1. Stop

    The [Exit] method of the [Environment] class allows you to stop the execution of a program:

    1

    3.9. Enumerations

    An enumeration is a data type whose value domain consists of a set of named integer constants. Consider a program that needs to handle exam grades. There are five possible grades: Pass, AssezBien, Good, TresBien, and Excellent. We can then define an enumeration for these five constants:

    1
    enum Mentions { Passable, AssezBien, Bien, TresBien, Excellent }

    Internally, these five constants are encoded as consecutive integers starting with 0 for the first constant, 1 for the next, and so on. We can also set these values explicitly: [enum Mentions { Passable = 10, AssezBien = 12, ... }]. A variable can be declared to take its values from the enumeration:

    1
    Mentions maMention = Mentions.Passable;

    A variable can be compared to the different possible values in the enumeration:

    1
2
3
4
    if (maMention == Mentions.Passable)
{
    Console.WriteLine("Peut mieux faire");
}

    Just as the simple type [int] is equivalent to the structure [System.Int32], every enumeration derives from the class [System.Enum]. This class has static methods that allow you to retrieve the values and names of an enumerated type:

    • [Enum.GetValues<Mentions>()] (.NET 5) returns the array of values for the enumeration [Mentions];
    • [Enum.GetNames<Mentions>()] returns the array of their names;
    • [Enum.TryParse(chaine, out Mentions m)] converts a string into an enumeration value.

    The 2008 course described [Enum.GetValues(typeof(Mentions))]: this form, which is still valid, returns an untyped array that must then be converted. The generic form [GetValues<Mentions>()] directly returns an array of type [Mentions[]].

    1

    Here, in the statement on line 2, [age] is the actual parameter that will pass its value to the formal parameter [a]. We are interested in how a formal parameter retrieves the value of an actual parameter.

    3.10.1. Passing Modes

    C# supports the following passing modes:

    • by value (the default mode): the value of the actual parameter is copied into the corresponding formal parameter. These are two distinct entities: if the function modifies the formal parameter, the actual parameter remains unchanged. This mode is suitable for a function’s input parameters;
    • by reference with [ref]: the actual parameter and the formal parameter are one and the same entity. If the function modifies the formal parameter, the actual parameter is also modified. The keyword [ref] must appear in both the function definition and the call. The actual parameter must have a value before the call. This mode is suitable for input-output parameters;
    • by reference with [out]: same as [ref], but the parameter is an output-only parameter: the actual parameter does not need an initial value, and the function must assign a value to the formal parameter. This is the mode used by the [TryParse] methods. Starting with C# 7, the variable can be declared in the call: [out var x] or [out int x];
    • by read-only reference with [in] (C# 7.2): the parameter is passed by reference, which avoids copying, but the function cannot modify it. This mode is only useful for large structures; for predefined types, passing by value is just as efficient.

    3.10.2. Optional parameters, named arguments, variable number of parameters

    C# 4 introduced optional parameters: a parameter can be given a default value in the function definition; the caller can then omit it. Optional parameters are placed after the required parameters. It also introduced named arguments: when calling the function, an actual parameter can be preceded by the name of the formal parameter followed by a colon. This allows an optional parameter that precedes other parameters to be omitted, or for parameters to be provided in any order.

    The keyword [params] allows you to write a function with a variable number of parameters: the last formal parameter is an array, and the caller can pass either an array or a list of values (which may be empty), which the compiler arranges into an array. Starting with C# 13, the parameter [params] can also be of another collection type, such as [List<T>] or [ReadOnlySpan<T>].

    3.11. Local Functions and Tuples

    3.11.1. Local functions

    A local function (C# 7) is a function defined within a method or, as in our examples, among top-level statements. It can only be used in that location. Since our programs no longer have classes, local functions replace the static methods from the 2008 examples. A local function:

    • can be called before it is defined;
    • can use the local variables surrounding it, unless it is declared as [static]: the [static] keyword (C# 8) ensures that it depends only on its parameters, making it easier to understand. We declare our local functions [static] whenever possible;
    • may have an expression body: [static int Carre(int x) => x * x;] is equivalent to a body like [{ return x * x; }].

    In a larger program, we write classes and methods: this is the subject of the next chapter.

    3.11.2. Tuples

    A tuple (C# 7) groups multiple values—which may be of different types—into a single entity. The type [(int, string)] denotes a pair consisting of an integer and a string; its elements are called [Item1] and [Item2]. They can be named: [(int Numero, string Nom)]. A tuple can be deconstructed: [var (numero, nom) = t;] assigns its elements to two variables.

    Tuples allow a function to return multiple values without using parameters [out]: this is often more readable.
