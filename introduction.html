    This document is a product of Anthropic’s IA Claude. It is a rewrite, for C# 14 and the .NET 10 platform, of the course “Learning C# Version 3.0 with the .NET 3.5 framework, written by Serge Tahé in May 2008. It retains the course outline, examples, and central theme, while updating the language, libraries, and tools:

    • the 2008 course used C# 3.0 and the .NET 3.5 framework on Windows with Visual C# 2008 Express. Since then, C# has seen eleven major versions (from C# 4.0 in 2010 to C# 14 in 2025), and the .NET platform has been completely rewritten: it is now open-source, cross-platform (Windows, Linux, macOS), and released annually. This document uses .NET 10 (November 2025, long-term support version) and C# 14;
    • the chapter on Windows Forms graphical user interfaces has been removed: today, business applications are most often written with web interfaces. The “User Events” chapter, which followed it, has been reworked into a chapter on delegates, lambda expressions, and events, without forms;
    • Two chapters are new: asynchronous programming ([Task] tasks and the [async] / [await], introduced in 2012 with C# 5) and Entity Framework Core, the object-relational mapping tool for .NET. The chapter on commonly used .NET classes now covers LINQ (the 2008 course explicitly stated that it did not cover this);
    • the tools have changed: the [VS Code] editor (or the IDE and [Visual Studio 2026]) and the [dotnet] command replace Visual C# 2008 Express; the [MSTest] testing framework replaces [NUnit 2]; the dependency injection provided by [Microsoft.Extensions.DependencyInjection] replaces [Spring.NET]; SGBD, [MySQL] (provided by [Laragon]) and the [MySqlConnector] connector replace SQL Server 2005 Express; the [HttpClient] class replaces [WebClient] and [WebRequest], which have been deprecated; the REST / JSON web services written with ASP.NET Core replace the SOAP and [ASMX] web services;
    • anything that has become obsolete has been removed or marked as such, and each chapter presents the latest features of the language and platform as of the time of writing.

    This document is not a comprehensive course. Like the 2008 edition, it is intended for readers who already have programming experience and want to learn the basics of C#. It uses examples: more than two hundred programs (nearly three hundred C# files), most of them short, with line-by-line comments.

    1.1. C# and .NET from 2002 to 2026

    C# was released in February 2002, alongside Microsoft’s .NET 1.0 platform, to which it is tied. The .NET platform is a runtime environment similar to the Java Virtual Machine: the compilers for the .NET languages (C#, F#, VB.NET) generate intermediate code (IL, “Intermediate Language”) that the .NET virtual machine (the CLR, “Common Language Runtime”) compiles on the fly into machine code. All classes on the platform are available to all .NET languages.

    In 2008, the course stated that .NET ran only on Windows and that the Mono project allowed it to be used, to a limited extent, on Unix and Linux. The situation has changed significantly:

    • 2016: .NET Core 1.0. Microsoft has released a new implementation of .NET, which is open source (MIT license, code available on GitHub) and cross-platform: Windows, Linux, and macOS. The old “.NET” framework (.NET Framework 4.x) remains supported for legacy Windows applications but is no longer being developed;
    • 2020: .NET 5. .NET Core becomes simply “.NET”: a single platform for all uses (console, web, desktop, mobile, cloud);
    • Since 2020: A new version of .NET is released every year in November. Even-numbered versions (.NET 6, 8, 10) have extended support (LTS, three years); odd-numbered versions (.NET 7, 9) have standard support (STS: eighteen months, extended to two years starting with .NET 9). Each version of .NET introduces a new version of C#;
    • November 2025: .NET 10 (LTS) and C# 14, which are used in this document. .NET 10 is supported through November 2028.

    The 2008 course also noted that in 2002, C# was largely a copy of Java and that it was easy to switch between the two, but that the two languages had since developed their own distinct characteristics. The gap has widened: Over the course of its various versions, C# has incorporated concepts from functional languages (lambda expressions, LINQ, pattern matching, records, immutable types), asynchronous programming ([async] / [await], which JavaScript, Python, and Rust have since adopted), and a type system that detects null references at compile time.

    1.3. The Common Thread: Tax Calculation

    As in 2008, the same problem is revisited throughout the document: calculating the income tax for a taxpayer who has only their salary to report. The tax bracket used is that of the original course (2003 income): it is no longer current, but it suffices for our purpose, which is to write the same application in several different ways. It is implemented in nine versions:

    Version
    Chapter
    Content
    1
    3
    A single program: validated input, calculation, display
    2
    4
    Classes and interfaces: [TrancheImpot], [IImpot], [AbstractImpot], [HardwiredImpot]
    3
    5
    calculation data read from a text file or a JSON file
    4
    6
    A layered architecture ([dao], [metier], [ui]) within a single project
    5
    6
    One library per layer, unit tests, and integration of layers via dependency injection
    6
    10
    A [dao] layer that reads data from a MySQL database using ADO.NET
    7

    8

    9
    13

    Starting with version 5, subsequent versions reuse the layers from version 5 and replace only the layer that has changed: this is the whole point of the layered architecture presented in Chapter 6.

    The small programs are single-file applications: a single file named [.cs], executed by the command [dotnet run fichier.cs] (Chapter 2). Multi-file programs are projects ([.csproj]) grouped into a solution ([.slnx]) by chapter.

    All programs in this document were compiled without errors or warnings using SDK .NET 10, and then executed. The results reproduced in the document are those from these executions. They were obtained in the French locale (fr-FR), as on a French Windows workstation: real numbers are displayed with a decimal point, and dates are in French. Two notes:

    • error messages from the .NET platform (exception messages) are in English: .NET does not provide French translations for these messages;
    • the examples were run on Linux. For the most part, this makes no difference: .NET is cross-platform. The few differences (file paths with / instead of \, line endings) are noted where they occur.

    The results of multithreaded, asynchronous, or network programs, as well as the measured execution times, may vary from one run to another: the comments focus on what is reproducible.
