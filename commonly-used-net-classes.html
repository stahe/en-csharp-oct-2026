    5. Commonly Used .NET Classes

    Here we present a few frequently used classes from the .NET platform: strings, arrays, collections, files, and regular expressions. We’ll also cover LINQ (Language Integrated Query), which the 2008 course omitted even though it had already been available since C# 3: it is now the most common way to manipulate collections in C#. Before that, we’ll show you how to find information about the thousands of available classes. This guide is indispensable for any C# developer, even experienced ones.

    The examples in this chapter—with the exception of the sample application at the end—are single-file applications run by [dotnet run fichier.cs]. They are located in the [05-classes-dotnet] folder of the course code and run in the French (fr-FR) locale.

    5.1. Finding Help on .NET Classes

    The 2008 course provided a detailed description, complete with screenshots, of the MSDN help installed with Visual Studio 2008. This local help is no longer available: the .NET documentation is now online, free of charge, and updated with each new version.

    5.1.1. Online Documentation

    The starting point is Microsoft’s learn.microsoft.com website. There you’ll find:

    • C# language documentation: https://learn.microsoft.com/fr-fr/dotnet/csharp/. It includes an overview of the language, tutorials, the language reference (keywords, operators, statements), and a “What’s New” section that describes each version of C#;
    • the .API .NET reference: https://learn.microsoft.com/fr-fr/dotnet/api/. It describes, namespace by namespace, all classes in .NET: their constructors, properties, and methods, with examples;
    • the API browser, on the same page: a search box where you can type a class or method name ([StringBuilder], [Regex.Match]…). A drop-down list allows you to select the version of .NET (here, .NET 10).

    The page for a class, such as System.String, displays:

    • the class’s namespace and the assembly that contains it;
    • its declaration, parent class, and the interfaces it implements;
    • a list of its constructors, properties, and methods, each with a link to a detailed page showing its various overloads, parameters, return values, possible exceptions, and often an example;
    • notes on its usage.

    The pages are available in French (machine translation) and English (original text, which is sometimes more precise). You can switch between them by replacing [fr-fr] with [en-us] in the URL. A search on a search engine using the class’s full name (“System.Text.StringBuilder”) usually leads directly to the correct page.

    5.1.2. Editor Help

    The code editor (Visual Studio, Visual Studio Code with the C# Dev Kit extension, Rider) provides immediate help without having to leave the code:

    • autocompletion (IntelliSense): after typing [uneChaine.], the editor suggests a list of the object’s properties and methods, along with a summary of each;
    • Tooltips: Hovering the mouse over a class, method, or variable name displays its declaration and a summary of its documentation;
    • Parameter help: When you type the opening parenthesis of a call, the editor displays the different overloads of the method and the role of each parameter;
    • Go to Definition (F12 key): Displays the declaration of the class or method. For a .NET class, the editor displays the public declarations reconstructed from the assembly, along with their documentation comments;
    • In Visual Studio, pressing the F1 key on a class or method name opens the corresponding page in the online documentation.

    These documentation comments, which are visible when you hover over an element, are the ones used to generate the online reference. You can write similar comments in your own code using the [/// <summary> ... </summary>] syntax placed above a class or method: the editor will display them in the same way.

    It is important to note that a string of the type [string] is immutable; it cannot be modified after it is created. Thus, [s1.Trim()] returns the string [s2], and [s1] and [s2] are two different strings: [s1] has not changed.

    A string [c] can be considered a read-only array of characters:

    • [c[i]] is the i-th character of [c] (the first character is number 0);
    • [c.Length] is the number of characters in [c].

         // End of entry if string is empty
        if (reponse == "")
        {
            break;
        }
         // check the input
        if (!double.TryParse(reponse, out double element))
        {
            Console.WriteLine("Saisie incorrecte, recommencez");
            continue;
        }

// searching the array for elements entered via the keyboard
static void Recherche(double[] elements, TypeRecherche type)
{
    while (true)
    {
        Console.Write("Elément cherché (rien pour arrêter) : ");
        string reponse = (Console.ReadLine() ?? "").Trim();
         // Done?
        if (reponse == "")
        {
            break;
        }
         // verification
        if (!double.TryParse(reponse, out double element))
        {
            Console.WriteLine("Erreur, recommencez...");
            continue;
        }
         // Searching for the element in the array
        int i = type == TypeRecherche.Dichotomique
            ? Array.BinarySearch(elements, element)    // sorted array
            : Array.IndexOf(elements, element);        // arbitrary array
         // displaying the answer
        Console.WriteLine(i >= 0 ? $"Trouvé en position {i}" : $"Pas dans le tableau ({i})");
    }
}

    5.4. Generic Collections

    In addition to arrays, there are various classes for storing collections of elements. Generic collections, introduced with .NET 2.0, are located in the [System.Collections.Generic] namespace, which is part of the implicit [using] namespaces. We will first introduce two frequently used collections—the list and the dictionary—and then briefly cover others.

    The [System.Collections] namespace contains the older, non-generic versions of these collections, dating back to .NET 1.0: [ArrayList] (a list), [Hashtable] (a dictionary)... The 2008 course still featured [ArrayList]. These classes are now obsolete: they store references of type [object], which requires casting the read elements and boxing the numbers into objects, with associated memory and time costs. Generic collections have none of these drawbacks: a *[List<int>] stores its integers directly in an internal *[int[]] array, and the compiler checks the type of the elements being added. [ArrayList] and [Hashtable] should no longer be used in new code.

    The value associated with the key [c] in a dictionary [d] is obtained using the notation [d[c]]. This value is both readable and writable. Thus, we can write:

    5.5. LINQ

    The 2008 course ended just before LINQ, introducing its anonymous types without actually using them. LINQ (Language Integrated Query, C# 3, 2007) is a set of methods that allow you to query a collection just as you would query a database: filter, sort, group, calculate totals, and so on. It applies to any collection that implements the [IEnumerable<T>] interface: arrays, lists, dictionaries, sets, lines in a file, results of a regular expression, and, with Entity Framework Core (Chapter 11), database tables. The [System.Linq] namespace is part of the implicit [using] namespace.

    5.7.2. The JSON serialization

    Writing and reading a binary file byte by byte is tedious, and even the slightest discrepancy between writing and reading produces incorrect results. It is generally preferable to serialize objects: automatically convert them into a sequence of bytes or characters, then deserialize them to reconstruct them.

    .NET provided the [BinaryFormatter] class for this purpose, which serialized objects into a binary format specific to .NET. It has now been removed: it was declared obsolete in .NET 5, and its implementation was removed in .NET 9, because deserializing data from an untrusted source with [BinaryFormatter] allowed arbitrary code to be executed. Microsoft recommends replacing it with the JSON serialization from the [System.Text.Json] library, which has been integrated into .NET since .NET Core 3.0.

    JSON (JavaScript Object Notation) is a text-based, human-readable, and universal format: it is the exchange format for web services (Chapter 13) and numerous configuration files. An object is written within curly braces in the form of "property":value pairs, with arrays enclosed in square brackets.

    5.8. Regular Expressions

    The [System.Text.RegularExpressions.Regex] class supports the use of regular expressions. These allow you to validate the format of a string. For example, you can verify that a string representing a date is indeed in the dd/mm/yy format. To do this, you use a pattern and compare the string to that pattern. In this example, d, m, and y must be digits. The pattern for a valid date format is therefore [\d\d/\d\d/\d\d], where the symbol [\d] represents a digit. The symbols that can be used in a pattern are as follows:

    character
    description
    [\]
    marks the following character as a special character or literal. For example, [n] corresponds to the character n, [\n] corresponds to a newline character, [\\] corresponds to \, and [\(] corresponds to (
    [^]
    corresponds to the beginning of the string
    [$]
    corresponds to the end of the string
    [*]
    matches the preceding element zero or more times. Thus, [zo*] matches z or zoo
    [+]
    matches the previous element one or more times. Thus, [zo+] matches "zoo," but not "z"
    [?]
    matches the preceding element zero or one time. For example, [a?ve?] matches “ve” in “lever”
    [.]
    matches any single character, except for a newline character
    [(modèle)]
    searches for the pattern and stores the match (a group). The matching substring can be extracted from the [Groups] collection in the result. To find matches with characters in parentheses, use [\(] or [\)]
    [x|y]
    matches either x or y. For example, [z|foot] matches z or foot; [(z|f)oo] matches zoo or foo
    [{n}]
    n is a non-negative integer. Corresponds exactly n times to the previous element. For example, [o{2}] does not correspond to o in Bob, but to the first two o’s in fooooot
    [{n,}]
    matches the previous element at least n times. For example, [o{2,}] does not match the 'o' in 'Bob', but matches all the 'o's in 'fooooot'. [o{1,}] is equivalent to [o+], and [o{0,}] is equivalent to [o*]
    [{n,m}]

    protected abstract TrancheImpot[] TranchesImpot { get; }

     // tax calculation
    public int Calculer(bool marie, int nbEnfants, int salaire)
    {
         // calculation of the number of shares
        decimal nbParts = (decimal)nbEnfants / 2 + (marie ? 2 : 1);
        if (nbEnfants >= 3)
        {
            nbParts += 0.5m;
        }
         // Calculation of taxable income and the family quotient
        decimal revenu = 0.72m * salaire;
        decimal quotient = revenu / nbParts;
         // Determination of the tax bracket: the last one is used if no other bracket applies
        TrancheImpot[] tranches = TranchesImpot;
        TrancheImpot tranche = tranches[^1];
        for (int i = 0; i < tranches.Length - 1; i++)
        {
            if (quotient <= tranches[i].Limite)
            {
                tranche = tranches[i];
                break;
            }
        }
         // tax calculation
        return (int)(revenu * tranche.CoeffR - nbParts * tranche.CoeffN);
    }
}

namespace ImpotsV3;

// the tax brackets read from a text file of lines delimited by:coeffR:coeffN
public partial class FileImpot : AbstractImpot
{
     // the field separator: the character: surrounded by spaces if present
    [GeneratedRegex(@"\s*:\s*")]
    private static partial Regex Separateur();

     // tax brackets read from the file
    private readonly TrancheImpot[] tranchesImpot;

     // Implementation of the parent class’s abstract property
    protected override TrancheImpot[] TranchesImpot => tranchesImpot;

    public FileImpot(string nomFichier)
    {
         // the filename (without the path) for error messages
        string nom = Path.GetFileName(nomFichier);
         // the tax brackets read; their number is unknown in advance
        List<TrancheImpot> tranches = [];
        try
        {
            int numLigne = 0;
            foreach (string ligneLue in File.ReadLines(nomFichier))
            {
                numLigne++;
                string ligne = ligneLue.Trim();
                 // empty lines are ignored
                if (ligne == "")
                {
                    continue;
                }
                 // the line must have three fields
                string[] champs = Separateur().Split(ligne);
                if (champs.Length != 3)
                {
                    throw new ImpotException($"Ligne n° {numLigne} incorrecte ({ligne})")
                    {
                        Code = (int)CodeErreur.Ligne
                    };
                }
                 // three positive or zero decimal numbers, written with a decimal point
                CodeErreur code = 0;
                if (!Lire(champs[0], out decimal limite)) code |= CodeErreur.Champ1;
                if (!Lire(champs[1], out decimal coeffR)) code |= CodeErreur.Champ2;
                if (!Lire(champs[2], out decimal coeffN)) code |= CodeErreur.Champ3;
                if (code != 0)
                {
                    throw new ImpotException($"Ligne n° {numLigne} incorrecte ({ligne})")
                    {
                        Code = (int)code
                    };
                }
                 // the new tax bracket is stored
                tranches.Add(new TrancheImpot(limite, coeffR, coeffN));
            }
        }
        catch (Exception e) when (e is IOException or UnauthorizedAccessException)
        {
             // File access error: wrap it in a ImpotException
            throw new ImpotException($"Erreur lors de la lecture du fichier {nom}", e)
            {
                Code = (int)CodeErreur.Acces
            };
        }
         // At least one tax bracket is required
        if (tranches.Count == 0)
        {
            throw new ImpotException($"Le fichier {nom} ne contient aucune tranche")
            {
                Code = (int)CodeErreur.Ligne
            };
        }
         // Transfer the list to the tax bracket array
        tranchesImpot = tranches.ToArray();
    }

     // Converting a field to a decimal value >= 0, regardless of the machine's locale
    private static bool Lire(string champ, out decimal valeur) =>
        decimal.TryParse(champ, NumberStyles.AllowDecimalPoint, CultureInfo.InvariantCulture, out valeur);
}

    Comments:

    • Line 7: The class [FileImpot] is derived from the class [AbstractImpot], just as the class [HardwiredImpot] was in version 2. It is declared as [partial] because it contains a generated regular expression;
    • lines 10–11: the regular expression for the field separator in a boundary line: coeffR:coeffN: the character [:], preceded and followed by any number of spaces;
    • lines 14–17: the read chunks, returned by the property [TranchesImpot], which redefines the abstract property of [AbstractImpot];
    • line 19: the constructor receives the name of the text file containing the data. Its role is to populate the array [tranchesImpot];
    • line 22: the file name without its path, used in error messages. The constructor actually receives a full path, which does not need to be displayed to the user;
    • line 24: Reading a text file is sequential: the number of lines is not known until the entire file has been read. Therefore, the array cannot be sized in advance; the chunks are temporarily stored in a list;
    • line 28: The file is read line by line using [File.ReadLines], which opens and closes the file itself. The 2008 course used [StreamReader];
    • lines 38–43: The line is split into fields using a regular expression; if there are not three fields, a [ImpotException] exception with code [Ligne] is thrown. The 2008 course stored the error in a variable, exited the loop, and then threw the exception after closing the file: throwing it immediately is simpler, and [File.ReadLines] closes the file in any case, since the loop [foreach] releases its counter even when an exception interrupts it;
    • lines 47–55: conversion of the three fields to decimal numbers. Errors are accumulated in the variable [code] using the operator [|=], then reported together;
    • lines 83–84: conversion of a field. [NumberStyles.AllowDecimalPoint] allows only digits and a decimal point: no signs, spaces, or thousands separators. Negative numbers are therefore rejected, which validates the data at the same time as it is converted. [CultureInfo.InvariantCulture] enforces the period as the decimal separator, regardless of the machine’s locale;
    • lines 62–67: file access errors ([IOException] and its variants, such as [FileNotFoundException], or [UnauthorizedAccessException] for insufficient permissions) are wrapped in a [ImpotException] with code [Acces]. The [when (...)] exception filter (C# 6) intercepts only these exceptions: [ImpotException] exceptions thrown within the loop are not intercepted and exit the constructor unchanged. The pattern [e is IOException or UnauthorizedAccessException] is a pattern of type combined by [or] (C# 9);
    • lines 71–79: an empty file is rejected; otherwise, the list is transferred to the slice array, which was the purpose of the constructor.

    Encapsulating low-level exceptions ([IOException]) into an application-specific exception ([ImpotException]) allows the calling code to handle only one type of exception, regardless of the data source: a text file, a JSON file, and, later in the course, a database.

             // Reading the file

            };

        {
            throw new ImpotException($"Le fichier {nom} contient une valeur négative")
            {
                Code = (int)CodeErreur.Json
            };
        }
        tranchesImpot = tranches;
    }

    5.10. Conclusion

    This chapter has introduced the .NET classes used in almost all programs:

    • immutable strings ([string]) and strings ([StringBuilder]) for building them piece by piece; interpolation with widths and formats, raw strings; views ([ReadOnlySpan<char>]) for critical code;
    • the arrays and the [Array] class;
    • generic collections [List<T>], [Dictionary<TKey,TValue>], [HashSet<T>], [Queue<T>], [Stack<T>], [PriorityQueue<TElement,TPriority>], and their read-only interfaces; the non-generic collections [ArrayList] and [Hashtable] are deprecated;
