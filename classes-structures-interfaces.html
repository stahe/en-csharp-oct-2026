    4.1. Objects by Example

    4.1.1. Overview

    We will now explore object-oriented programming through examples. An object is an entity that contains data defining its state (referred to as fields, attributes, etc.) and functions (referred to as methods). An object is created based on a template called a class:

    Starting from the previous class [C1], you can create many objects such as [O1], [O2], … All of them will have the fields [p1], [p2], … and the methods [M3], [M4], … However, they will have different values for their [pi] fields, thus each having its own unique state. If [o1] is an object of type [C1], [o1.p1] refers to the field [p1] of [o1], and [o1.M3] refers to the method [M3] of [o1].

    Here we have the definition of a class, and thus a data type. When we create variables of this type, we call them objects or class instances. A class is therefore a template from which objects are constructed.

    The members of a class can be data (fields), methods (functions), or properties. Properties are special methods used to retrieve or set the value of an object’s fields. These members can be accompanied by one of the following keywords:

    Keyword
    Access
    [private]
    A private member is accessible only by the class’s internal methods. This is the default access level
    [public]
    A public member is accessible by any method, whether or not it is defined within the class
    [protected]
    A protected member is accessible only through the internal methods of the class or a derived class (see the concept of inheritance below)
    [internal]
    An internal member is accessible by any method within the same assembly (the same project)

    In general, a class’s data is declared private, while its methods and properties are declared public. This means that the user of an object (the programmer):

    • will not have direct access to the object’s private data;
    • can call the object’s public methods, including those that provide access to its private data.

    4.1.4. The Initialize method

    What is the purpose of the [Initialize] method? Because [lastName], [firstName], and [age] are private members of the [Person] class, the statements:

    1
2
3
4
    Person p1;
p1.firstName = "Jean";
p1.lastName = "Dupont";
p1.age = 30;

    are invalid. We need to initialize an object of type [Person] using a public method. This is the purpose of the [Initialize] method. We’ll write:

    1
2
    Person p1;
p1.Initialize("Jean", "Dupont", 30);

    The notation [p1.Initialize] is valid because [Initialize] is publicly accessible.

    4.1.5. The new operator

    However, the previous sequence of statements is incorrect. The statement

    1
    Person p1;

    declares [p1] as a reference to an object of type [Person]. This object does not yet exist, and therefore [p1] is not initialized. When we then write [p1.Initialize("Jean", "Dupont", 30)], we call the method [Initialize] of the object referenced by [p1]. However, this object does not exist, and the compiler reports the error: the local variable [p1] has not been assigned a value. If we write:

    1
2
    Person? p1 = null;
p1.Initialize("Jean", "Dupont", 30);

    we explicitly indicate with the keyword [null] that the variable [p1] does not yet reference any object (the question mark in [Person?] indicates that the variable may be set to [null]). The compiler then issues only a warning (dereferencing a null reference), and at runtime, the method call throws a [NullReferenceException] exception. For [p1] to reference an object, you must write:

    1
    Person p1 = new Person();

    This creates an object of type [Person] that has not yet been initialized: its fields have their default values, in this case the empty string for [lastName] and [firstName], and 0 for [age] (a numeric field without an explicit initial value is 0; a reference-type field is [null]). Now that [p1] references an object, the initialization statement for that object, [p1.Initialize("Jean", "Dupont", 30)], is valid.

    4.1.6. The this keyword

    Let’s look at the code for the [Initialize] method:

    11
12
13
14
15
16
        public void Initialize(string p, string n, int age)
    {
        this.firstName = p;
        this.lastName = n;
        this.age = age;
    }

    The statement [this.firstName = p] means that the field [firstName] of the current object ([this]) is assigned the value [p]. The keyword [this] refers to the current object—the one on which the method is being executed. How do we know this? Let’s look at how the object referenced by [p1] is initialized in the calling program:

    1
    p1.Initialize("Jean", "Dupont", 30);

    It is the method [Initialize] of the object [p1] that is called. When, within this method, the object [this] is referenced, it actually refers to the object [p1]. The method [Initialize] could also have been written as follows:

    1
2
3
4
5
6
        public void Initialize(string p, string n, int age)
    {
        firstName = p;
        lastName = n;
        this.age = age;
    }

    When a method of an object references a field [A] of that object, the notation [this.A] is implied. It must be used explicitly when there is a conflict of identifiers. This is the case with the statement [this.age = age;], where [age] refers to both a field of the current object and the parameter [age] received by the method. In this case, the ambiguity must be resolved by referring to the field [age] as [this.age].

    4.1.10. Constructors of the Person class

    A constructor is a method that bears the name of the class and is called when the object is created. It is generally used to initialize the object. It is a method that can accept parameters but does not return a value. Its declaration is not preceded by any type (not even [void]).

    If a class [C] has a constructor that accepts n parameters, the declaration and initialization of an object of this class can be done as follows:

    1
    C obj = new C(arg1, arg2, ... argn);

    or

    1
2
3
    C obj;
...
obj = new C(arg1, arg2, ... argn);

    When a class [C] has one or more constructors, one of these constructors must be used to create an object of that class. If a class [C] has no constructors, it has a default constructor, which is the parameterless constructor [public C()]. The object’s fields then retain their initial values. This is what happened in the previous programs, where we had written [new Person()].

    • lines 17–21: the “main” constructor initializes the three fields. Since its parameters have the same names as the fields, the fields are distinguished using [this];

An object [StringBuilder], on the other hand, is a mutable string: its method [Append] adds characters to the string without creating a new object.

    4.1.17. Automatic properties

    In many cases, the methods [get] and [set] of a property simply read from and write to a private field without any further processing. In such cases, you can use an automatic property declared as follows:

    1
    public Type Property { get; set; }

    The private field associated with the property is not declared; it is automatically generated by the compiler and can only be accessed through its property. Thus, instead of writing the field [firstName] and the property [FirstName] for the program [classes-07.cs], you can write:

    1
        public string FirstName { get; set; } = "";

    without declaring the private field [firstName]. The expression [= ""] following the property is the initial value of the hidden field. The difference between the two properties is that the first one validates the first name in [set], while the second one performs no validation.

    Is using the automatic property [FirstName] equivalent to declaring a public field [public string FirstName;]? For the user of the class, the syntax is the same. However, declaring a class field as public is not recommended: it violates the concept of encapsulation of an object’s state, which should be private and exposed through public methods. With an automatic property, checks can be added later in [set] without changing the code of the class’s users.

    4.2. Inheritance by Example

    4.2.1. Overview

    Here we discuss the concept of inheritance. The purpose of inheritance is to “customize” an existing class so that it meets our needs. Suppose we want to create a class named [Teacher]: a teacher is a specific type of person. They have attributes that other people do not have: the subject they teach, for example. But they also have the attributes common to all people: first name, last name, and age. A teacher is therefore a full member of the class [Person] but has additional attributes. Rather than creating a class [Teacher] from scratch, we prefer to build upon the existing class [Person] and adapt it to the specific characteristics of teachers. The concept of inheritance allows us to do this.

    To indicate that the class [Teacher] inherits the properties of the class [Person], we write:

    1
    public class Teacher : Person

    [Person] is called the parent (or base) class, and [Teacher] is called the derived (or child) class. A [Teacher] object has all the characteristics of a [Person] object: it has the same fields and methods. These fields and methods from the parent class are not repeated in the definition of the child class; we simply specify the fields and methods added by the child class. A C# class can be derived from only one parent class.

    4.2.4. Polymorphism

    Consider a class hierarchy: C0 ← C1 ← C2 ← … ← Cn, where Ci ← Cj indicates that class Cj is derived from class Ci. This implies that class Cj has all the characteristics of class Ci plus additional ones. Let Oi be objects of type Ci. It is valid to write [Oi = Oj] with j > i. Indeed, by inheritance, class Cj has all the characteristics of class Ci plus additional ones. Therefore, an object Oj of type Cj contains an object of type Ci. The operation [Oi = Oj] causes Oi to be a reference to the object of type Ci contained within the object Oj.

    The fact that a variable Oi of class Ci can actually reference not only an object of class Ci but any object derived from class Ci is called polymorphism: the ability of a variable to reference different types of objects.

    Let’s take an example and consider the function [Display] from the previous program:

    The class [Teacher] in the [Inheritance2] project is declared as [public sealed class Teacher : Person].     4.3. Redefining the meaning of an operator for a class

    4.3.1. Introduction

    Consider the expression [op1 + op2], where [op1] and [op2] are two operands. It is possible to redefine the meaning of the operator [+]. If the operand [op1] is an instance of class [C1], a static method must be defined in class [C1] with the following signature:

    1
    public static Type operator +(C1 operand1, C2 operand2)

    When the compiler encounters the expression [op1 + op2], it translates it to [C1.operator +(op1, op2)]. The type returned by the method [operator] is important. In fact, consider the operation [op1 + op2 + op3]. It is translated by the compiler as [(op1 + op2) + op3]. Let [res12] be the result of [op1 + op2]. The next operation performed is [res12 + op3]. If [res12] is of type [C1], it will also be translated to [C1.operator +(res12, op3)]. This allows operations to be chained together.

    Unary operators with only one operand can also be redefined. Thus, if [op1] is an object of type [C1], the operation [op1++] can be redefined by a static method of the [C1] class:

    1
    public static C1 operator ++(C1 operand1)

    What has been stated here applies to most operators, with a few exceptions:

    • Operators [==] and [!=] must be redefined together, as must [<] and [>], [<=] and [>=];
    • the operators [&&], [||], [=], [.], [?:], [??], and [new] cannot be redefined;
    • up to C# 13, the compound assignment operators ([+=], [-=], …) could not be overridden: [a += b] was always compiled to [a = a + b]. C# 14 allows them to be overridden, as we will see.

        get

    {

        return standardDeviation.Value;

    {
        if (Grades.Count == 0)
        {
            return -1;
        }
        double sum = 0;
        foreach (Grade grade in Grades)
        {
            sum += grade.Value;
        }
        return sum / Grades.Count;
    }

    {
        if (Grades.Count == 0)
        {
            return -1;
        }
        double m = Average;
        double squares = 0;
        foreach (Grade grade in Grades)
        {
            squares += Math.Pow(grade.Value - m, 2);
        }
        return Math.Sqrt(squares / Grades.Count);
    }

    public override string ToString()
    {
        return $"subject={Subject}, grades=({string.Join(",", Grades)})";

    Meaning

    4.8.3. A generic interface: IComparer<T>

    To illustrate the concept of a generic interface, we will sort an array of people first by their names, then by their ages. The method that allows us to sort an array is the static method [Sort] of the class [Array]. It has different signatures (it is overloaded). We will use the following signature:

    1
    public static void Sort<T>(T[] array, IComparer<T>? comparer)

    [Sort] is a generic method where [T] denotes any type. The method takes two parameters:

    • [T[] array]: the array of elements of type [T] to be sorted;
    • [IComparer<T>? comparer]: a reference to an object that implements the [IComparer<T>] interface.

    [IComparer<T>] is a generic interface defined as follows (simplified definition):

    1
2
3
4
    public interface IComparer<in T>
{
    int Compare(T? x, T? y);
}

    The [IComparer<T>] interface has only one method. The [Compare] method:

    • takes two parameters, [x] and [y], of type [T]. The type [T?] indicates that their values can be [null] (the keyword [in] is a technical detail that we will not explain here);
    • returns a positive number if x > y, 0 if x == y, and a negative number if x < y. It is up to the developer to define the meaning of the operators <, ==, and >. For example, if [p1] and [p2] are two [Person] objects, we can say that p1 > p2 if the name of [p1] comes after the name of [p2] in alphabetical order. This will result in an ascending sort based on the people’s names. If we want to sort by age, we’ll say that p1 > p2 if the age of [p1] is greater than the age of [p2];
    • to sort in descending order, simply reverse the sign of the results.

    4.9. Namespaces

    To write a line on the screen, we use the [Console.WriteLine(...)] statement. If we look at the definition of the class [Console] in the documentation for .NET, we find that it is part of the namespace [System]. This means that the class [Console] should be referred to as [System.Console], and we should actually write [System.Console.WriteLine(...)]. We avoid this by using a [using] clause:

    1
2
3
    using System;
...
Console.WriteLine(...);

    This means that the [System] namespace is imported along with the [using] clause. When the compiler encounters a class name (in this case, [Console]), it searches for it in the various namespaces imported by the [using] clauses. Here, it finds the class [Console] in the namespace [System]. In a recent .NET project, we don’t even need to write [using System;]: this namespace is included in the project’s implicit **using** statements, as we saw at the beginning of the chapter.

    The documentation provides a second piece of information about the [Console] class: the assembly that contains it, the [System.Console.dll] file. An assembly is the result of compiling a project: a [.dll] file (library) or an executable. To use the classes in an assembly, the compiler must be aware of it. The 2008 course demonstrated how to pass these references to the [csc] compiler via the command line ([csc /r:fic1.dll /r:fic2.dll prog.cs]). Today, we no longer call the compiler directly: the assemblies of the .NET framework are referenced automatically, and the [.csproj] file references the other libraries, either as packages ([PackageReference]), or as projects ([ProjectReference]), as we will see in Chapter 6, which is devoted to layered architectures.

    When creating a class, you can create it within a namespace. The purpose of these namespaces is to avoid name conflicts between classes, for example, when they are distributed. Consider two companies, E1 and E2, distributing packaged classes in the assemblies [e1.dll] and [e2.dll], respectively. Suppose a client C purchases these two sets of classes, in which both companies have defined a class named [Person]. If the client’s program uses the class [Person], the compiler will not know whether to use the class [Person] from [e1.dll] or the one from [e2.dll]. It will report an error. If the company E1 creates its classes in a namespace named [E1] and the company E2 creates its classes in a namespace named [E2], the two classes named [Person] will then be named [E1.Person] and [E2.Person]. The client must use either [E1.Person] or [E2.Person] (or an alias) in its classes, but not [Person]. The namespace resolves this ambiguity.

    4.14. Nullable reference types

    Since the beginning of this chapter, our projects have had nullable reference types enabled ([<Nullable>enable</Nullable>] in [.csproj], an option enabled by default in single-file applications). The principle is as follows:

    • A variable, field, parameter, or reference-type result declared without a question mark—for example, of type [Person]—is never supposed to be equal to [null];
    • if it can be [null], it is declared with a question mark: [Person?];
    • the compiler analyzes the program flow and issues a warning whenever a potentially null value is used without verification, or assigned to a non-nullable variable.

    The language does not prohibit anything at runtime: these are compilation warnings, but a program that compiles without warnings is much less prone to the [NullReferenceException] exception, the most common runtime error.     private static readonly decimal[] limits = [4962m, 8382m, 14753m, 23888m, 38868m, 47932m, 0m];
    private static readonly decimal[] coeffR = [0m, 0.068m, 0.191m, 0.283m, 0.374m, 0.426m, 0.481m];
    private static readonly decimal[] coeffN = [0m, 291.09m, 1322.92m, 2668.39m, 4846.98m, 6883.66m, 9505.54m];

    // the tax brackets
    private readonly TaxBracket[] taxBrackets;

    // constructor
    public HardwiredTax()
    {
        // creation and filling of the array of tax brackets
        taxBrackets = new TaxBracket[limits.Length];
        for (int i = 0; i < taxBrackets.Length; i++)
        {
            taxBrackets[i] = new TaxBracket(limits[i], coeffR[i], coeffN[i]);
        }
    }

    // implementation of the abstract property of the parent class
    protected override TaxBracket[] TaxBrackets => taxBrackets;
}

    using TaxV2;

// interactive tax calculation program
// the user types three data items on the keyboard: married nbChildren salary
// the program then displays the tax to pay

const string syntax = """
    syntax: Married NbChildren Salary
    Married: y for married, n for not married
    NbChildren: number of children
    Salary: annual salary in euros
    """;

// creation of an ITax object
ITax tax = new HardwiredTax();

// input loop
while (true)
{
    // we ask for the tax calculation parameters
    Console.Write("Tax calculation parameters in the format: Married (y/n) NbChildren Salary, or nothing to stop: ");
    string parameters = (Console.ReadLine() ?? "").Trim();
    // anything to do?
    if (parameters == "")
    {
        break;
    }
    // checking the number of fields of the typed line
    string[] fields = parameters.Split(' ', StringSplitOptions.RemoveEmptyEntries);
    if (fields.Length != 3)
    {
        Console.WriteLine(syntax);
        continue;
    }
    // checking the validity of the parameters
    // married
    string married = fields[0].ToLower();
    if (married != "y" && married != "n")
    {
        Console.WriteLine(syntax + "\nIncorrect married argument: type y or n");
        continue;
    }
    // nbChildren
    if (!int.TryParse(fields[1], out int nbChildren) || nbChildren < 0)
    {
        Console.WriteLine(syntax + "\nIncorrect NbChildren argument: type a positive or zero integer");
        continue;
    }
    // salary
    if (!int.TryParse(fields[2], out int salary) || salary < 0)
    {
        Console.WriteLine(syntax + "\nIncorrect salary argument: type a positive or zero integer");
        continue;
    }
    // the parameters are correct: we calculate the tax
    Console.WriteLine($"Tax={tax.Calculate(married == "y", nbChildren, salary)} euros");
}

    • Line 15: Creation of a [tax] object that implements the [ITax] interface. This object is obtained by instantiating a type [HardwiredTax], a type that implements the [ITax] interface.
