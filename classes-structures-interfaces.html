    The members of a class can be data (fields), methods (functions), or properties. Properties are special methods used to retrieve or set the value of an object’s fields. These members can be accompanied by one of the following keywords:

    Keyword
    Access
    [private]
    A private member is accessible only by the class’s internal methods. This is the default access level
    [public]
    A public member is accessible by any method, whether or not it is defined within the class
    [protected]

    • will not have direct access to the object’s private data;
    • can call the object’s public methods, including those that provide access to its private data.

    4.1.4. The Initialize method

    What is the purpose of the [Initialise] method? Because [nom], [prenom], and [age] are private members of the [Personne] class, the statements:

    1
2
3
4
    Personne p1;
p1.prenom = "Jean";
p1.nom = "Dupont";
p1.age = 30;

    are invalid. We need to initialize an object of type [Personne] using a public method. This is the purpose of the [Initialise] method. We’ll write:

    1
2
    Personne p1;
p1.Initialise("Jean", "Dupont", 30);

    The notation [p1.Initialise] is valid because [Initialise] is publicly accessible.

    4.1.5. The new operator

    However, the previous sequence of statements is incorrect. The statement

    1
    Personne p1;

    declares [p1] as a reference to an object of type [Personne]. This object does not yet exist, and therefore [p1] is not initialized. When we then write [p1.Initialise("Jean", "Dupont", 30)], we call the method [Initialise] of the object referenced by [p1]. However, this object does not exist, and the compiler reports the error: the local variable [p1] has not been assigned a value. If we write:

    1
2
    Personne? p1 = null;
p1.Initialise("Jean", "Dupont", 30);

    we explicitly indicate with the keyword [null] that the variable [p1] does not yet reference any object (the question mark in [Personne?] indicates that the variable may be set to [null]). The compiler then issues only a warning (dereferencing a null reference), and at runtime, the method call throws a [NullReferenceException] exception. For [p1] to reference an object, you must write:

    1
    Personne p1 = new Personne();

    This creates an object of type [Personne] that has not yet been initialized: its fields have their default values, in this case the empty string for [nom] and [prenom], and 0 for [age] (a numeric field without an explicit initial value is 0; a reference-type field is [null]). Now that [p1] references an object, the initialization statement for that object, [p1.Initialise("Jean", "Dupont", 30)], is valid.

    4.1.6. The this keyword

    Let’s look at the code for the [Initialise] method:

    The statement [this.prenom = p] means that the field [prenom] of the current object ([this]) is assigned the value [p]. The keyword [this] refers to the current object—the one on which the method is being executed. How do we know this? Let’s look at how the object referenced by [p1] is initialized in the calling program:

    1
    p1.Initialise("Jean", "Dupont", 30);

    It is the method [Initialise] of the object [p1] that is called. When, within this method, the object [this] is referenced, it actually refers to the object [p1]. The method [Initialise] could also have been written as follows:

    1

4

    public void Initialise(string p, string n, int age)
{
    prenom = p;
    nom = n;
    this.age = age;
}

    When a method of an object references a field [A] of that object, the notation [this.A] is implied. It must be used explicitly when there is a conflict of identifiers. This is the case with the statement [this.age = age;], where [age] refers to both a field of the current object and the parameter [age] received by the method. In this case, the ambiguity must be resolved by referring to the field [age] as [this.age].

    4.1.10. Constructors of the Person class

    A constructor is a method that bears the name of the class and is called when the object is created. It is generally used to initialize the object. It is a method that can accept parameters but does not return a value. Its declaration is not preceded by any type (not even [void]).

    If a class [C] has a constructor that accepts n parameters, the declaration and initialization of an object of this class can be done as follows:

    1

...

If a class [C] has no constructors, it has a default constructor, which is the parameterless constructor [public C()]. The object’s fields then retain their initial values.     4.1.17. Automatic properties

    In many cases, the methods [get] and [set] of a property simply read from and write to a private field without any further processing. In such cases, you can use an automatic property declared as follows:

    1
    public Type Propriété { get; set; }

    The private field associated with the property is not declared; it is automatically generated by the compiler and can only be accessed through its property. Thus, instead of writing the field [prenom] and the property [Prenom] for the program [classes-07.cs], you can write:

    1
    public string Prenom { get; set; } = "";

    without declaring the private field [prenom]. The expression [= ""] following the property is the initial value of the hidden field. The difference between the two properties is that the first one validates the first name in [set], while the second one performs no validation.

    Is using the automatic property [Prenom] equivalent to declaring a public field [public string Prenom;]? For the user of the class, the syntax is the same. However, declaring a class field as public is not recommended: it violates the concept of encapsulation of an object’s state, which should be private and exposed through public methods. With an automatic property, checks can be added later in [set] without changing the code of the class’s users.

    4.2. Inheritance by Example

    4.2.1. Overview

    Here we discuss the concept of inheritance. The purpose of inheritance is to “customize” an existing class so that it meets our needs. Suppose we want to create a class named [Enseignant]: a teacher is a specific type of person. They have attributes that other people do not have: the subject they teach, for example. But they also have the attributes common to all people: first name, last name, and age. A teacher is therefore a full member of the class [Personne] but has additional attributes. Rather than creating a class [Enseignant] from scratch, we prefer to build upon the existing class [Personne] and adapt it to the specific characteristics of teachers. The concept of inheritance allows us to do this.

    To indicate that the class [Enseignant] inherits the properties of the class [Personne], we write:

    1
    public class Enseignant : Personne

    [Personne] is called the parent (or base) class, and [Enseignant] is called the derived (or child) class. A [Enseignant] object has all the characteristics of a [Personne] object: it has the same fields and methods. These fields and methods from the parent class are not repeated in the definition of the child class; we simply specify the fields and methods added by the child class. A C# class can be derived from only one parent class.

    4.2.4. Polymorphism

    Consider a class hierarchy: C0 ← C1 ← C2 ← … ← Cn, where Ci ← Cj indicates that class Cj is derived from class Ci. This implies that class Cj has all the characteristics of class Ci plus additional ones. Let Oi be objects of type Ci. It is valid to write [Oi = Oj] with j > i. Indeed, by inheritance, class Cj has all the characteristics of class Ci plus additional ones. Therefore, an object Oj of type Cj contains an object of type Ci. The operation [Oi = Oj] causes Oi to be a reference to the object of type Ci contained within the object Oj.

    The fact that a variable Oi of class Ci can actually reference not only an object of class Ci but any object derived from class Ci is called polymorphism: the ability of a variable to reference different types of objects.

    Let’s take an example and consider the function [Affiche] from the previous program:

    4.2.7. Sealed classes

    The class [Enseignant] in the [Heritage2] project is declared as [public sealed class Enseignant : Personne]. The keyword [sealed] (sealed) prevents classes from being derived from the class [Enseignant]: the declaration [class EnseignantChercheur : Enseignant] would be rejected by the compiler. A class is sealed when it is not intended to be derived from; the compiler and the runtime can also optimize calls to its virtual methods. The keyword also applies to a redefined method or property: [public sealed override string Identite] would prevent derived classes from redefining it again, without prohibiting derivation from the class.

    Conversely, a method or property that is not declared as [virtual], [abstract] (see below), or [override] cannot be overridden with [override]: in C#, unlike in Java, methods are not virtual by default.

    4.3. Redefining the meaning of an operator for a class

    4.3.1. Introduction

    Consider the expression [op1 + op2], where [op1] and [op2] are two operands. It is possible to redefine the meaning of the operator [+]. If the operand [op1] is an instance of class [C1], a static method must be defined in class [C1] with the following signature:

    1
    public static Type operator +(C1 operande1, C2 operande2)

    When the compiler encounters the expression [op1 + op2], it translates it to [C1.operator +(op1, op2)]. The type returned by the method [operator] is important. In fact, consider the operation [op1 + op2 + op3]. It is translated by the compiler as [(op1 + op2) + op3]. Let [res12] be the result of [op1 + op2]. The next operation performed is [res12 + op3]. If [res12] is of type [C1], it will also be translated to [C1.operator +(res12, op3)]. This allows operations to be chained together.

    Unary operators with only one operand can also be redefined. Thus, if [op1] is an object of type [C1], the operation [op1++] can be redefined by a static method of the [C1] class:

    1
    public static C1 operator ++(C1 operande1)

    What has been stated here applies to most operators, with a few exceptions:

    • Operators [==] and [!=] must be redefined together, as must [<] and [>], [<=] and [>=];
    • the operators [&&], [||], [=], [.], [?:], [??], and [new] cannot be redefined;
    • up to C# 13, the compound assignment operators ([+=], [-=], …) could not be overridden: [a += b] was always compiled to [a = a + b]. C# 14 allows them to be overridden, as we will see.

    Why define the operator [+=] when [l = l + p] produces the same output? // a stack of elements of type T
class Pile<T>
{
     // the elements in the stack
    private readonly List<T> elements = new List<T>();

     // number of elements
    public int Count => elements.Count;

     // adding an element to the top of the stack
    public void Empiler(T element)
    {
        elements.Add(element);
    }

     // removing the element at the top of the stack
    public T Depiler()
    {
        if (elements.Count == 0)
        {
            throw new InvalidOperationException("pile vide");
        }
        T element = elements[^1];
        elements.RemoveAt(elements.Count - 1);
        return element;
    }
}

    4.8.3. A generic interface: IComparer<T>

    To illustrate the concept of a generic interface, we will sort an array of people first by their names, then by their ages. The method that allows us to sort an array is the static method [Sort] of the class [Array]. It has different signatures (it is overloaded). We will use the following signature:

    1
    public static void Sort<T>(T[] tableau, IComparer<T>? comparateur)

    [Sort] is a generic method where [T] denotes any type. The method takes two parameters:

    • [T[] tableau]: the array of elements of type [T] to be sorted;
    • [IComparer<T>? comparateur]: a reference to an object that implements the [IComparer<T>] interface.

    [IComparer<T>] is a generic interface defined as follows (simplified definition):

    1
2
3
4
    public interface IComparer<in T>
{
    int Compare(T? x, T? y);
}

    The [IComparer<T>] interface has only one method. The [Compare] method:

    • takes two parameters, [x] and [y], of type [T]. The type [T?] indicates that their values can be [null] (the keyword [in] is a technical detail that we will not explain here);
    • returns a positive number if x > y, 0 if x == y, and a negative number if x < y. It is up to the developer to define the meaning of the operators <, ==, and >. For example, if [p1] and [p2] are two [Personne] objects, we can say that p1 > p2 if the name of [p1] comes after the name of [p2] in alphabetical order. This will result in an ascending sort based on the people’s names. If we want to sort by age, we’ll say that p1 > p2 if the age of [p1] is greater than the age of [p2];
    • to sort in descending order, simply reverse the sign of the results.

    4.9. Namespaces

    To write a line on the screen, we use the [Console.WriteLine(...)] statement. If we look at the definition of the class [Console] in the documentation for .NET, we find that it is part of the namespace [System]. This means that the class [Console] should be referred to as [System.Console], and we should actually write [System.Console.WriteLine(...)]. We avoid this by using a [using] clause:

    1
2
3
    using System;
...
Console.WriteLine(...);

    This means that the [System] namespace is imported along with the [using] clause. When the compiler encounters a class name (in this case, [Console]), it searches for it in the various namespaces imported by the [using] clauses. Here, it finds the class [Console] in the namespace [System]. In a recent .NET project, we don’t even need to write [using System;]: this namespace is included in the project’s implicit **using** statements, as we saw at the beginning of the chapter.

    The documentation provides a second piece of information about the [Console] class: the assembly that contains it, the [System.Console.dll] file. An assembly is the result of compiling a project: a [.dll] file (library) or an executable. To use the classes in an assembly, the compiler must be aware of it. The 2008 course demonstrated how to pass these references to the [csc] compiler via the command line ([csc /r:fic1.dll /r:fic2.dll prog.cs]). Today, we no longer call the compiler directly: the assemblies of the .NET framework are referenced automatically, and the [.csproj] file references the other libraries, either as packages ([PackageReference]), or as projects ([ProjectReference]), as we will see in Chapter 6, which is devoted to layered architectures.

    When creating a class, you can create it within a namespace. The purpose of these namespaces is to avoid name conflicts between classes, for example, when they are distributed. Consider two companies, E1 and E2, distributing packaged classes in the assemblies [e1.dll] and [e2.dll], respectively. Suppose a client C purchases these two sets of classes, in which both companies have defined a class named [Personne]. If the client’s program uses the class [Personne], the compiler will not know whether to use the class [Personne] from [e1.dll] or the one from [e2.dll]. It will report an error. If the company E1 creates its classes in a namespace named [E1] and the company E2 creates its classes in a namespace named [E2], the two classes named [Personne] will then be named [E1.Personne] and [E2.Personne]. The client must use either [E1.Personne] or [E2.Personne] (or an alias) in its classes, but not [Personne]. The namespace resolves this ambiguity.

    4.14. Nullable reference types

    Since the beginning of this chapter, our projects have had nullable reference types enabled ([<Nullable>enable</Nullable>] in [.csproj], an option enabled by default in single-file applications). The principle is as follows:

    • A variable, field, parameter, or reference-type result declared without a question mark—for example, of type [Personne]—is never supposed to be equal to [null];
    • if it can be [null], it is declared with a question mark: [Personne?];
    • the compiler analyzes the program flow and issues a warning whenever a potentially null value is used without verification, or assigned to a non-nullable variable.

    The language does not prohibit anything at runtime: these are compilation warnings, but a program that compiles without warnings is much less prone to the [NullReferenceException] exception, the most common runtime error.     We’ll revisit the tax calculation we covered in the previous chapter (Version 1) and implement it using classes and interfaces. Let’s review the problem. We aim to write a program to calculate a taxpayer’s tax. We’ll consider the simplified case of a taxpayer who has only a single salary to report (using the 2004 tax schedule for 2003 income, kept as-is: this is an exercise):

    The 2008 course used a structure with three automatic read-write properties. We use an immutable record structure ([readonly record struct]):

    • a structure because a slice is a small piece of data without an identity, defined solely by its value: an array of slices directly contains the slices, without a separate object in memory for each one. With three [decimal] (48 bytes), the structure exceeds the size of approximately 16 bytes usually recommended for a structure; this is not a problem here: there are few segments, and they are copied only when they are read;
    • immutable ([readonly]) because there is no reason for a tax bracket segment to be modified once it has been created. The 2008 course, incidentally, modified the limit of the last tax bracket segment during the calculation—a side effect that we are eliminating;
    • a record ([record]) because the compiler generates the constructor, the properties, [ToString], and the equality operator from a single line.

public abstract class AbstractImpot : IImpot
{
     // The tax brackets needed for the calculation come from an external source
     // known only to derived classes
    protected abstract TrancheImpot[] TranchesImpot { get; }

     // tax calculation
    public int Calculer(bool marie, int nbEnfants, int salaire)
    {
         // Calculation of the number of shares
        decimal nbParts = (decimal)nbEnfants / 2 + (marie ? 2 : 1);
        if (nbEnfants >= 3)
        {
            nbParts += 0.5m;
        }
         // Calculation of taxable income and the family quotient
        decimal revenu = 0.72m * salaire;
        decimal quotient = revenu / nbParts;
         // Determination of the tax bracket: the last one is used if no other bracket applies
        TrancheImpot[] tranches = TranchesImpot;
        TrancheImpot tranche = tranches[^1];
        for (int i = 0; i < tranches.Length - 1; i++)
        {
            if (quotient <= tranches[i].Limite)
            {
                tranche = tranches[i];
                break;
            }
        }
         // tax calculation
        return (int)(revenu * tranche.CoeffR - nbParts * tranche.CoeffN);
    }
}
    • Line 3: The class [AbstractImpot] implements the interface [IImpot];
    • line 7: the scale data, in the form of a protected abstract property. The class [AbstractImpot] does not know where this data comes from (written in the code, read from a file, a database, etc.). It leaves this up to the derived classes. This is why it is declared abstract, which prevents it from being instantiated. The 2008 course used a protected field that derived classes had to initialize; the abstract property requires derived classes to provide it: the compiler verifies this;
    • lines 10–33: the implementation of the [Calculer] method of the [IImpot] interface. Derived classes will not need to rewrite this method. The [AbstractImpot] class thus serves as a factorization class for the derived classes: it contains what is common to all of them;
    • line 13: the number of shares. The conversion [(decimal)nbEnfants] is essential: without it, [nbEnfants / 2] would be an integer division (3 / 2 = 1). The expression [marie ? 2 : 1] equals 2 for a married taxpayer, 1 otherwise;
    • Lines 19–20: taxable income and the family quotient. All calculations are performed using [decimal], a type adapted to the amounts: the suffix [m] of [0.72m] denotes a constant of this type;
    • Lines 22–29: Determining the tax bracket. By default, this is the last bracket ([tranches[^1]], line 23). The loop iterates through all brackets except the last one and stops ([break]) at the first bracket whose limit is greater than or equal to the family quotient;
    • line 33: tax calculation. The conversion [(int)] truncates the result [decimal] to its integer part.

public class HardwiredImpot : AbstractImpot
{
     // tax calculation data (2004 tax schedule for 2003 income), hard-coded
    private static readonly decimal[] limites = [4962m, 8382m, 14753m, 23888m, 38868m, 47932m, 0m];
    private static readonly decimal[] coeffR = [0m, 0.068m, 0.191m, 0.283m, 0.374m, 0.426m, 0.481m];
    private static readonly decimal[] coeffN = [0m, 291.09m, 1322.92m, 2668.39m, 4846.98m, 6883.66m, 9505.54m];

     // Tax brackets
    private readonly TrancheImpot[] tranchesImpot;

     // generator
    public HardwiredImpot()
    {
         // Creation and population of the tax bracket table
        tranchesImpot = new TrancheImpot[limites.Length];
        for (int i = 0; i < tranchesImpot.Length; i++)
        {
            tranchesImpot[i] = new TrancheImpot(limites[i], coeffR[i], coeffN[i]);
        }
    }

     // Implementation of the parent class’s abstract property
    protected override TrancheImpot[] TranchesImpot => tranchesImpot;
}
